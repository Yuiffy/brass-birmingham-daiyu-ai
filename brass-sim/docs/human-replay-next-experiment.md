## 第一优先级：生产链必须付得起、来得及

当前 `world_model/human_strategy.js` 的未来现金估值允许后续贷款，却没有充分扣除贷款占用
的行动机会；`readiness` 的重复建造收益也可能高估资金、手牌和槽位的可达性。深度 2 搜索
难以看到研发—贷款—建造—连接—用酒—出售整条链。这是代码层面的待检验假设，尚无因果实验。

先做一个有界链规划器，返回预计收益、全部现金支出、所需贷款次数和行动数，而非只增加研发奖励：

1. 从当前合法产业候选开始，列出所需研发、建造、资源购买、连接、备酒和出售动作。
2. 逐步核算现金与收入变化；把贷款当作一次真实行动，按规则扣减收入并影响后续现金。
3. 检查剩余行动、可用牌和槽位；若无法完整兑现，降低或取消未兑现收益。
4. 仅为少数高潜力候选扩展这些链；记录额外搜索时间，避免无限加深。

开发回归局面包括现金不足研发、临近时代结束的未出售产业、竞争导致酒被取走、需要贷款
才能完成的生产链、收入为负时的资金短缺。现有最低 71 分留出局若用于修改策略，就将其
明确改列为开发材料；不得再次作为下一轮的最终独立证据。

## 第二优先级：酒、顺序与时代交替

将以下问题转成可执行的合成局面测试，明确标注“受赛报启发”，而非声称重建真实棋盘：

- 运河最后两次行动：立即出售用掉对手酒，还是留自有酒进入铁路时代？
- 铁路开局：现金、煤和酒是否允许双铁路，前一人的消费能否打断该计划？
- 产业出售与双铁路争夺同一份酒时，比较整条收益链与对手可能的响应。

先审计相关规则和候选动作；规则缺失时，增加搜索只会更擅长利用模拟器缺陷。
当前农场、商人、完整牌堆与资源/弃牌选择尚未全面审计，真实回放导入前必须处理相应差异。

## 第三优先级：有条件的产业路线与保留手牌

依据商人需求、手牌、空位和他人布局决定棉花、制造品、陶器的可兑现路线。
比较不同弃牌选择，避免为即时小收益丢掉后续陶器或覆盖所需的关键牌。
最终实战模式还应隐藏其他玩家手牌；现有公共手牌实验不能作为隐藏信息对局的强度认证。

## 把人类决策做成可审计数据

每条视频标注至少保存以下字段：

```json
{
  "source_url": "视频或回放地址",
  "timestamp_seconds": 0,
  "engine": "目标引擎及版本",
  "rules": "规则及数据版本",
  "observed_state": {},
  "unknown_fields": ["未展示的手牌"],
  "observed_action": {},
  "alternatives": [],
  "reason": "可见证据或解说依据",
  "confidence": "high/medium/low",
  "terminal_label_usable": false
}
```

这是数据格式草案，不是已采集样本。不得猜出未知手牌或未展示的资源选择。只在选项可确认
合法、未知信息不会改变选择比较时，用局部材料做动作偏好或情境检验。只有完整、合法且
能审计到终局的轨迹才提供价值训练标签。按整场比赛切分训练与验证，不能把同一场的相邻
局面分别放入训练和测试。

仓库已有 Rust 路线 `training/human_replay.py`，能从浏览器 SQLite 回放审计人类动作和
终局标签；`training/demonstration_prior.py` 能把人类动作意图做成合法动作上的平滑先验。
当前没有找到可用的真人回放文件。这些是现成基础，但其特征和权重不能直接塞进 JavaScript
模型；需要明确选择 Rust 的完整回放训练，或为 JS 实现对应导入与审计。

## 世界模型的具体下一步

将当前更强的 `human-guide-v1` 对局单独作为**合成教师数据**，扩展
`world_model/collect_value.js` 接受教师策略配置并记录双铁路转移，再训练价值头和动力学。
它现在并未接入这一教师，也没有因这轮攻略调整而重训。

先检验合法双铁路的转移预测、价值排序及完整对局表现，再决定是否提高学习价值的混合比例。
人类示范、攻略情境和合成对局分别记录来源；不能把自对弈称为真实人类数据。
世界模型能否追上真实引擎引导搜索需要新实验，不能由单步预测精度推断。

## 下一轮比较与停止条件

- 比较对象冻结为当前 `human-guide-v1`，保留代码和模型哈希；不再只对弱的旧原版宣传增分。
- 先分别做融资链、酒竞争、弃牌选择的消融；同时给出相近计算预算下的比较。
- 正式测试采用候选对三个当前版，以及四席候选自对弈，各 30 个新种子组、四座位轮换，
  每组 120 局。当前版在同种子同席位运行对应参照阵容。
- 新种子在代码冻结后生成并保存协议，不接触旧留出种子用于最终成绩；若据新成绩继续修改，
  再保留下一批新种子。
- 报告均分、种子组置信区间、胜率、10% 分位数、低于 100 分比例、140/150 比例和每步成本。
  另外记录 pass、贷款行动、未出售产业、未兑现研发及铁路开局双铁路失败原因。
- 若均分上升但低分尾部恶化或依赖规则漏洞，不晋升默认版本。150 分保持为挑战目标，
  真人胜负水平另需合法隐藏信息规则与真实棋手对局验证。

建议第一轮只实现“完整链的融资与行动预算”，以减少低分局，并给后续真人偏好和世界模型
训练提供更可靠的教师。本文不新增权重、不改动既有正式成绩。
