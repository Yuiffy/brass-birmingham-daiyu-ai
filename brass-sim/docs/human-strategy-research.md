# 人类攻略到学习增强搜索 · 2026-10-09

目标：把可核对的公开策略用于 `guided` 学习增强搜索，测试四人局是否能更稳定地达到
140–150 分。所有正式比较使用 `economy-v2`，不加入终局收入奖励，不挑选高分种子。
这是模拟器内的策略实验；即使达到分数目标，也不能据此确认真人比赛水平。

## 实验约束

- 现有模型和来源报告保持可复现，候选独立配置；不覆盖旧权重。
- 先验证新合法动作与候选生成，再比较只补动作和加入攻略策略两种改动，区分收益来源。
- 开发种子与最终种子分开；正式结果冻结配置后才运行。
- 同种子完整轮换座位，置信区间按整个种子组计算。
- 报告平均、中位数、低分、140/150 分比例、动作分布、对手和计算成本。
- 除固定对手外，必须运行全桌候选自对弈，避免靠弱对手获得漂亮平均分。
- 使用学习价值头参与排序与搜索；人类策略作为可解释的引导，不把规则估值冒称为已训练的新模型。

## 初始诊断

原校准版四人 `guided` 在 120 局混合阵容中平均 70.82；`world` 为 27.83。
现有学习增强搜索仅生成单铁路，缺少攻略中反复提及的双铁路动作。
现有终局估值与深度 2 搜索难以覆盖研发—建造—出售的长链，且后续仅保留三个启发式候选。
这些诊断将由动作测试、消融和独立比赛检验。

## 正式结果：有提升，未达到稳定 140–150

三组各 120 局，合计 360 局；每组 30 个独立种子。自对弈按全部四名棋手统计，
混合桌只统计每局唯一候选棋手；重复轮换不增加统计独立性。

| 四人阵容 / 被统计棋手 | 平均 VP（95% 区间） | 中位数 | 10% 分位数 | ≥140 | ≥150 | 最低 / 最高 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 四席原版 / 所有棋手 | 78.28（75.61–80.95） | 78 | 62 | 0% | 0% | 42 / 117 |
| 候选对三个原版 / 候选棋手 | 121.61（119.00–124.06） | 124 | 100 | 12.5% | 0.83% | 82 / 152 |
| 四席攻略增强 / 所有棋手 | 124.38（121.47–127.18） | 124 | 103 | 19.17% | 6.67% | 71 / 173 |

同种子、同座位的配对增分为 **+43.33 VP，95% 区间 +39.97–46.66**。
候选对原版获胜 95%；自对弈 ≥140 比例的 95% 区间为 13.33–25.00%，
≥150 为 3.33–10.83%。本协议把至少 80% 达阈值作为“稳定”的检验条件；两项目标均未达到。
最高 173 分不能代表平均水平，也没有达到新的真人水平认证。

提升不只是击败弱对手：同策略自对弈均分仍为 124.38，线路得分也高于混合桌。
混合桌候选平均产业得分 74.45，道路 43.66；全候选桌产业 67.78，道路 53.77。
与原版自对弈相比，终局现金从 £54.03 降到约 £19，研发和建造增加，铺单路与贷款减少。
本机并发测试平均每步原版约 142 ms、攻略增强约 253–278 ms；受并发负载影响，
这些是运行成本记录，未作为架构性能基准。

低分尾部仍存在：候选自对弈有 8.33% 的棋手低于 100 分。最低 71 分局的运河时代
先研发、现金耗尽后出现三次 pass，铁路期多次贷款，最终只建七个产业，表明融资和
完整兑现链仍会失配。该局来自正式留出种子；本轮只记录问题，未据此继续调参。

开发期两组种子的 8 局试验：原版自对弈 77.50；仅双铁路和候选扩展 82.38；
第一版攻略估值 110.63；调整兑现链与覆盖规则后 124.13。
这些小样本仅用于诊断，且后两版间还含规则修复，不能当作单因素因果证据。
正式成绩采用上表，不引用开发最高分宣传。

正式记录在 `world_model/experiments/human-guide-20261009/`：
`summary.json`、冻结协议、三份完整比赛记录（`*.json.gz`，含每一步行动和源代码/权重哈希）。
压缩只改变存储格式。分析程序可直接读取压缩文件；重新跑比赛会生成普通 JSON。
世界模型本轮没有重训或正式复测；上轮 27.83 分的对手与引擎版本不同，不放入本轮排名。

## 最终实现

- 校准网络动作逐条铺路后消耗煤。双铁路使用 £15、两煤、一酒、一个弃牌；
  第二条可接第一条，对手酒必须连接第二条，商人酒不能铺双铁路。失败不改棋局。
- 修复运河时代同城市覆盖自己低级产业的候选，仍限制一个自有产业；
  覆盖对手耗尽资源产业也必须同种类且更高级。
- `human-guide-v1` 用 20% 冻结价值网络 + 80% 攻略估值排序。
  估计跨时代计分、产业出售所需连接与酒、资源供过于求、实际道路图标、
  随剩余行动递减的现金价值，以及研发后可重复建造的收益链。
- 每次根节点最多评估 64 个候选，后续最多 12 个候选；保留深度 2、宽度 8。
  对手行动选择自身估值较高的分支。原版分别为 32、3 个候选。
  因此本实验比较整个策略组合，不能将结果解释为等计算预算下网络架构优胜。
- 未读取真实未来牌序。沿用现有编码的 **所有手牌可见** 实验设定，尚未改成真人对局的隐藏手牌。
  世界模型动力学和价值权重均未重训；新增策略使用真实引擎推演，不让旧动力学预测双铁路。

## 使用与复现

在 `brass-sim/` 运行 `npm start -- --port 8086`，打开
`http://127.0.0.1:8086/?rules=economy-v2&strategy=human-guide-v1`。
选择“学习增强搜索”棋手；页面上的策略选项可切回原版。默认仍为原版。
AI 推演使用当前棋手配置；双铁路展示真实引擎预览和执行结果。
本轮接入 JavaScript 模拟器，未替换根目录 Rust AI。

正式协议在 `world_model/experiments/human-guide-20261009/protocol.json`。
两组开发种子仅用于两轮小样本调试，最终种子预先声明且不再调参。
以下命令无需重训，均在 `brass-sim/` 执行：

```sh
node world_model/human_benchmark.js --games 120 --seed 209900001 --workers 6 --out world_model/experiments/human-guide-20261009/mixed.json
node world_model/human_benchmark.js --games 120 --seed 209900001 --lineup baseline,baseline,baseline,baseline --workers 4 --out world_model/experiments/human-guide-20261009/baseline.json
node world_model/human_benchmark.js --games 120 --seed 210900001 --lineup human,human,human,human --workers 6 --out world_model/experiments/human-guide-20261009/selfplay.json
node world_model/human_analysis.js
npm test
python -m unittest discover -s tests -p training_test.py
```

比赛器强制 `economy-v2`，使用同一份四人价值网络，自动轮换全部席位。
每份报告有 30 个独立种子组；全同策略的轮换可能产生重复对局，不计作独立样本。
置信区间重采样整个种子组。配对增分比较同种子、同座位在候选混合桌和原版自对弈桌的成绩。
程序在运行前后检查计算代码与模型 SHA256，若运行期间改变就拒绝生成正式报告。
原版也使用相同修正规则，旧版 70.82 分不作为这轮配对基线。

## 验证与剩余边界

网络资源、覆盖规则、估值、未来牌序不变性和统计抽样均有回归测试。
浏览器验证包括四人开局、暂停、单步、重新推演不修改棋局、执行、继续，
以及双铁路一次执行支付、弃牌、两条线路和消耗酒；检查截图与浏览器错误。
复现控制测试：安装 Playwright，启动 demo 后运行 `node scripts/human-strategy-smoke.cjs`；
可用 `BRASS_DEMO_URL` 与 `BRASS_PLAYWRIGHT_MODULE` 指定服务及已有模块位置。

商人配置、产业数据、牌堆、农场建造、所有资源/商人/弃牌选择仍未完整审计或补全。
新道路估值只计当前棋盘图标；出售与资源兑现仍是近似，深度 2 无法完整推演长期竞争。
本轮只证明这个校准模拟器内的表现，不等同于真人四人比赛水平。
