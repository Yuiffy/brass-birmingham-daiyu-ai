# 旧版主界面与训练增强 AI

主站 `/` 保留 Svelte 实体棋盘、彩色扇形手牌、操作与存档。对手和实时分析统一
使用 `teacher_trained_v2_native_guided`，界面显示“学习增强 v2 · 2～4 人”。
AI 观战也支持 2～4 人。暂停、单步、继续、人工操作和旧存档均沿用原接口。

## 实际使用的模型

权重来自 `brass-sim/world_model/experiments/human-teacher-20261009/models/world-model.json`
的 `valueModel`：`brass-value-v2`、125 输入、epoch 105。只导出冻结价值头，完整
来源路径与源文件 SHA-256 保存在 `src/game/models/teacher-value.json` 中。
`scripts/export_teacher_value.cjs` 可重现导出与 JS 推理/语义特征对照样本。

这是教师＋保牌版的原生引擎适配，**不是原 JS 引擎上的完全相同棋手**。它保留
最新浏览器策略的 20% 教师价值、80% 真人策略组合，以及 64 根候选、8 条前瞻
分支、12 后继候选、两步深度。真人策略评估依据翻面概率、商人路线、共享酒、
线路收益、经济周转、研发与剩余手牌。

主站使用 Rust 的完整合法动作和规则：原经济规则策略只负责提出多样候选、
保留有价值的弃牌；最后排名由训练增强局面评估决定。原生特征以语义聚合和
原生线路地理对应训练特征，避免错误套用 JS 城市/动作编号。实际执行再次由
Rust 校验。纯世界模型的预测不替代真实转移。

与实验室公开全手牌设置不同，主站只保留当前棋手真实手牌，按公开牌数和已知
牌库组成采样对手手牌与未来牌堆。按城市和产业集合的语义排序先移除真实隐藏牌顺序（不使用含内存地址的 Debug 文本）；同一公开局面、
本手牌和种子给出确定性推荐，便于云端重建缓存。

权重嵌入主站二进制，Vercel 的 Rust 容器以 CPU 推理。不需要 GPU、本机启动
程序或 `FAST_BRASS_INFERENCE_URL`。`/ai-lab/` 仍使用原来的 JS 策略和独立存档。

## 云端存档

完整回放帧会超过 localStorage 的小容量限制，存档现保存在 IndexedDB；读取旧
localStorage 存档后，下一次成功请求会迁移到新数据库。保留原会话 JSON、手工
动作和回放记录。云请求允许最多 64 MiB 的会话包；重建推荐缓存不会重复追加
分析帧。存档仍属于当前浏览器，不会跨设备同步。

## 验证与测量边界

- Rust release 全部 125 个库测试通过，包含 5 个新适配检查、18 个 Web/云存档检查。
- 16 个独立 JS 推理样本与 Rust 冻结权重推理差异低于 1e-8；另外独立核对带
  建筑、线路、库存、经济与手牌变化的 125 维语义特征。
- 2/3/4 人推荐全部能在原生引擎执行；分析不改变当前状态。改变真实未来牌序
  和对手的隐藏牌分配不改变同一公开局面的推荐。
- 浏览器验证 2/3/4 人自动行动、暂停、单步、继续、评分解释、人工动作取消/
  确认/撤销、刷新恢复。保留旧棋盘与扇形手牌，控制台无错误。
- 通过实际云 API 完成 2/3/4 人共 307 次保存行动，并恢复终局，结果与离线同种子
  原生 screen 一致。3/4 人完整存档分别约 6.38/8.94 MB，已超过旧限制。证据
  `native-trained-ai-20261010/session-verification.json`；复现
  `node scripts/native-trained-session-smoke.cjs`。
- 浏览器实际装载 2/3/4 人完整大存档、刷新恢复及旧 localStorage 迁移通过，
  `native-trained-ai-20261010/save-verification.json`。
- 原生整局集成 screen 的原始合法动作与最终 VP/现金/收入在
  `native-trained-ai-20261010/screen.jsonl`。每局从种子独立合法回放并核对终局。
  复现：`cargo run --release --example trained_ai_benchmark -- 2 screen.jsonl`。

Screen 使用两组种子，各人数分别跑训练增强自弈与原规则自弈，共 12 局。这是
功能与性能检查，样本少，**不能证实跨人数强于原规则，也不是人体水平评级**。
模型迁移、隐藏牌、规则、候选提案均会改变对局结果；实验室已有的
163/152/128 均分不能直接当作主站均分，网页局面评分也不是终局分数或胜率。
